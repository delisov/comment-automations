Comment-triggered DM automations that respect every network's rules

Someone comments "pricing", gets a reply, gets a DM asking for their email, and gets the link once they answer. The plumbing is easy. The hard part is that Instagram, X, Bluesky, YouTube, WhatsApp and the rest each allow a different slice of that flow, under different time windows. This project is built around that.

What I built

A capability record per network

A small description of what each platform permits: private replies, messaging windows, who may message whom, limits. The editor, the validator and the engine are all driven by it, so a flow you can build is a flow that can run.

The engine

Postgres-only queue and timers, deduplication on the platform's event id, one active run per person with supersede, idempotent sends, and deadlines checked before every call.

The product UI

A ManyChat-simple constructor in Blotato's style, with immutable versions, runs and analytics compared across versions, including reply rate.

A test stand

A second service that emulates ten networks and enforces their public rules independently of the engine. You act as a user there and watch every call cross the boundary.

Try it in two minutes

  1. In the product, click New automation, pick @oqtastore on Instagram and give it a name.
  2. Add the keyword pricing, then the steps: reply to the comment, send a message asking for the email, wait for a reply, send the link. Publish.
  3. In the test stand, open the Instagram tab, act as @jane.doe and comment pricing please under a post.
  4. Watch the public reply and the private DM arrive. Answer the DM with an email address and the link follows.
  5. Back in the product, open Runs to see the timeline of that run, step by step.

This is a shared demo with no login, so others may be trying it at the same time. The stand's Reset restores the starting accounts, posts and users and keeps the automations. The clock buttons in the stand move time forward, which is how you see reminders, give-ups and closed messaging windows without waiting a day.

How it was made

  • I made the product and architecture decisions and reviewed the work; AI wrote the code under a gated process: isolated branches, independent reviews, verification on a real database, and a green CI before anything merged.
  • Three rounds of adversarial testing ran against the live system. Every finding came with a reproduction and was fixed, and each became a regression cycle.
  • No real platform credentials were used. The networks' rules come from their public documentation, encoded twice so a wrong assumption shows up as a failure instead of a passing test.
